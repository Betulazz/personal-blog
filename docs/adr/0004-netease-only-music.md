# ADR-0004: Use NetEase song identity as the only playlist source

Status: accepted for v2; amended by owner 2026-09-25; implemented with anonymous endpoint limits recorded in issue 07

The owner explicitly chose NetEase-only music and rejected preserving the v1 remote URL, local-media and S3-media playback alternatives. Administrators select songs by NetEase song ID; stable song identity is stored separately from runtime playback resolution, and the music page and mini-player control one shared audio instance.

The owner later confirmed that one administrator may QR-login to NetEase and that the account's personal paid entitlement may be shared with visitors. The official CLI documentation describes local-player playback but no browser-playable URL return contract. Because the blog's existing player runs in visitors' browsers, the owner explicitly authorized the reference repository's website endpoint approach as the fallback. The implementation therefore calls NetEase website endpoints for metadata and lyrics and returns its browser-facing media URL pattern. These are private, undocumented website interfaces, not official OpenAPI; they may change or stop working. This amendment supersedes the earlier prohibition on these endpoints. The selected fallback does not use the administrator's CLI session or paid entitlement, and the code must never expose account credentials or cookies. Legacy song records are privately archived as described in the [v2 specification](../../.scratch/personal-blog-v2/spec.md). Removing legacy playback support does not authorize deleting uploaded media files or changing storage used by other content.
